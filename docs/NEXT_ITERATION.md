# 下一轮：可持续更新的正式叙事版

制定日期：2026-11-03。状态：初始提案已实施并按用户反馈收敛为轻量滚动首页。最终范围见 [项目状态](../PROJECT.md)，下文保留原提案。当前用户已授权本地 Git；本文件回答后续迭代方式，不代表远端发布或自动同步已授权。

## 本轮目标

交付一个完整可浏览的正式页面，让读者理解跑步如何随生活阶段变化，能够深入核对记录，也能在以后同步数据时继续使用。沿用现有 React / Vite 运行入口，不新增另一份手工统计的独立页面。

叙事主线：习惯逐渐形成 → 2023 年育儿后的时间精力调整 → 近两年恢复与进阶。地点章节解释洛阳长期出差，并展示熟悉路线。已确认背景直接使用，不要求用户先补完全部经历。

## 参考方案的取舍

- 保留 Claude 概念稿的章节感、轨迹陈列、重点发现与明细入口。
- 把“性格报告”调整为有证据的行为与生活变化；不沿用“好奇”“一天不肯断”等未经确认的概括。
- “黎明”可以支持出发时间这一章节，但不能预先代替全站主线。最终名称、配色和版式服务于真实材料，不在开工前锁死。
- 旧概念稿保留作为参考；正式统计只从当前数据链计算。原始记录不为配合叙事而修改。

## 同一轮内的实施顺序

### 1. 建立可复算的展示口径

- 检查概念稿所称的 6 条重复记录，输出候选及保留/排除依据；无法确认时维持原始口径，并保留待核验项。
- 跑步默认 Run + VirtualRun，全运动地点分析明确另标范围。
- 统一累计、月度、出发时间、距离分布、配速、连续天数，文案中的数字与图表使用同一计算结果。
- 修正连续运动/连续跑步混用，以及最早记录、城市、比赛成绩的过度表述。
- 验收：每个关键结论可以追到日期范围、筛选规则和记录；相同口径的页面数字一致。

### 2. 做完整的叙事首页与档案入口

| 章节 | 要让人理解什么 | 核心材料与呈现 |
| --- | --- | --- |
| 开场：这些年一直有出发 | 长期关系中的延续 | 月度时间长卷；连续有记录的月份数自动计算 |
| 生活变了，节奏也会变 | 习惯如何适应生活 | 跑量/跑步日变化，叠加育儿与恢复背景；不虚构事件月份 |
| 同样是跑步，方式已经不同 | 用户所说的进阶具体体现在哪里 | 各阶段单次距离分布、长距离记录，必要时补充可比较的配速 |
| 熟悉的地方，异地的日常 | 路线与生活背景的联系 | 青岛等常跑轨迹、洛阳出差时期；地点记录不冒充连续居住证明 |

出发时间作为贯穿节奏章节的重要视角；比赛作为具体记录补充，不必额外增加同等分量的章节。累计公里数等保留为辅助信息。

读者可以顺序阅读，也可以从章节进入相应年份、地点或单次记录。复用现有记录表和地图能力，避免为叙事重写整个数据查阅系统。

人工背景继续维护在 `STORY.md`：优先构建时读取稳定事件条目，或生成页面所需派生数据，不再另建需要手工同步的一份故事真源。自动统计更新不覆盖原话。

验收：桌面和手机都能读懂主线；每个章节有明确发现和证据；详情可触摸/键盘访问，减少动效时仍完整可用。

### 3. 验证下一次更新能完整走通

- 用隔离测试数据验证跨年新增、空数据、缺失轨迹、未结束月份/年度；不把测试记录写入真实导出。
- 验证数字、年份范围和截至日期随数据更新，已确认背景不变。
- 检查文案里的“最高”“最近”“首次”等是否有明确边界，避免固定“九天前”等过时描述。
- 跑相关统计测试、前端构建与实际浏览验收；更新维护说明和日志。
- 按可验证阶段保存本地 Git 提交。暂不增加后台管理、远端服务、定时任务或复杂部署。

## 用户何时参与

现有资料足以开始。先由 AI 完成可读版本，再围绕实际页面挑 3—5 个影响理解的节点核对。优先了解“质的飞跃”对用户的具体含义，以及出发时间变化的背景；其余可以后补。

第一轮主要验证：是否像用户本人、育儿与恢复的关系是否表达准确、读者能否看见变化。以后再补照片、比赛记忆或细节，不预先把所有内容填满。
